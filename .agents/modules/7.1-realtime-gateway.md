## 范围

WebSocket 服务器 · 连接生命周期 · 心跳与超时 · 带回填的重连 · 事件扇出 ·
**跨两节点的 presence** · 语音 presence 与文字 presence 协调一致

## 明确不允许

- 修改 `packages/contracts/ws-events.*` 而不走 Tech Lead —— **本模块提议，Tech Lead 合并**
- 业务逻辑 —— 网关只负责传输和扇出

## Validation

```bash
pytest tests/realtime -v
# 压测：25 连接同时在线，断线重连风暴
```

## 完成标准

- [ ] 事件命名与载荷写进契约文件，其他模块只读
- [ ] 心跳超时后连接被清理，不泄漏
- [ ] **重连时能回填断线期间的消息**，不丢不重
- [ ] **一个人在语音里的状态和在文字里的状态是同一个** —— 不能出现「语音显示在线、文字显示离线」
- [ ] 两个媒体节点上的 presence 一致

## 备注

WS 事件是七个冻结契约里**唯一一个每个实时功能都要碰的面**。
它冻结得越晚，5.1 和 6.3 返工越多。

Redis 现在**不需要**。它在做多 LiveKit 节点、共享房间数据和跨节点路由时才引入 —— R02 之后再说。
