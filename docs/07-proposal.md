# Babacom 协作方案

> 一句话：**把两份规划文档做了一遍工程可行性评审，修掉里面会让项目翻车的矛盾，
> 并给出一套「多人 + 多 AI」能同时干活又不互相打架的机制。**

---

## 一、我解决了什么问题

### 1. 范围文档自相矛盾，照着做会撞墙

`scope.html` 的平台段写着 **Web only**，但功能表里同时要求「全局静音快捷键」和「共享系统音频」。

**这两个纯浏览器做不到。** 浏览器标签在全屏游戏时看不见键盘；浏览器只能分享标签页音频，抓不到游戏声。

→ **裁决为 Windows 客户端优先、Web 做访客入口。** 一条定了，「快捷键怎么做」那个悬而未决的问题当场消失 —— 它只在 web-only 假设下才是难题。

### 2. 回声消除被误当成「排除项」

34 项排除里包含回声消除、噪声抑制、自动增益。

**这三项是浏览器的默认行为，「排除」意味着主动写代码把它们关掉，比保留更费劲。** 而且只要有一个人不戴耳机，全房间就持续回声。

→ **恢复为必选**，默认开启、允许关闭。

### 3. 成本模型是空的，导致一个功能被排进了根本负担不起的位置

文档开头承诺给出「实际建造总成本」，正文一个数字都没有。我把它补上了：

| 画质 | 1 人共享 + 9 人观看 · 每月 30 小时 |
|---|---|
| 720p30 | ≈ 290 GB |
| 1080p30 | ≈ 530 GB |
| 1080p60 | ≈ 780 GB |
| **1440p60** | **≈ 1.5 TB** |

常见优质回国线路 VPS 的流量包是 500 GB–1 TB。

→ **1440p60 会在游戏夜当中静默触顶**，必须后置。这不是「以后再优化」，是算出来的硬结论。
→ Alpha 阶段月度固定成本 **$25–60**，超出说明有东西买早了。

### 4. 「13–16 周」和「84 个功能」是两个互相矛盾的数字

这个工期只对应**砍过的** Alpha，不对应全部功能。全部做完更接近 **30–50 个全职人周**（熟练单人全职 7–12 个月）。

两个数字写在同一份文档里，是目前最容易误导人的地方。

→ 拆清楚：砍后 Alpha ≈ 12–18 人周，全集 ≈ 30–50 人周。

### 5. 缺一个「稳定性」阶段，它必然会被挤掉

自动重连、睡眠唤醒、设备热插拔、自动更新、备份、监控 —— 这些散落在各个模块里，但发布顺序里**没有它们的位置**。

结果一定是：做完能演示的版本，然后一头扎进附件、表情、主题，重连问题永远排在下一轮。

→ **在「可玩」和「社交完善」之间插入一个不许塞新功能的稳定阶段。**
出口条件：连续两周游戏夜没人退回 Discord。

### 6. 没有端到端关卡，容易变成「三座石山最后粘一起」

24 个模块是横着切的，但没有任何里程碑要求「一条链路先跑通」。

→ 加一个硬关卡，**这条通了之前不开工其他功能 UI**；纵切片必需的最小 UI，以及 6.2 的设计令牌、共享组件和 i18n 基础除外，边界见 [3.1 模块](../.agents/modules/3.1-voice-channels.md)：

```
客户端启动 → 取 token → 加入房间 → 开麦
→ 另一台真实电脑（国内 ↔ 德国）听见 → 静音 → 退出
```

它一次性验证四个最贵的未知：token 契约、LiveKit 配置、跨境网络、客户端打包。

### 7. 两地服务器的架构误区

「亚洲一台 + 欧洲一台」**不会**自动让中德混合房间变快。

> **一个房间必须完整落在一个节点上。** 多区域部署能让不同房间落在不同节点，但不会把同一个房间切成「国内一半在亚洲、欧洲一半在欧洲」。

→ 这是唯一一条会改变架构的待决。给了三个方案，建议先做「房间级区域选择 + 只部署亚洲节点」，由实测决定够不够。

### 8. 功能表缺了运维侧的最小集

补入：移除成员 · 撤销会话 · 撤销邀请码 · 数据库迁移 · 发布回滚 · 网络诊断 · TURN 回退 · 设备热插拔 · 睡眠恢复。

这些不是锦上添花，是**没有它们就无法运营一台服务器**。

### 9. 省掉 4 万块

`baba.vip` 一年 ¥40000 没必要。WebRTC 部署要的是**可信域名 + 有效证书**，不是品牌域名，现有域名加子域就够：

```
app.<现有域名>   api.<现有域名>   rtc-asia.<现有域名>
```

→ 这笔钱应该花在那台走优质回国线路的媒体服务器上。**那笔钱决定产品能不能用，域名不决定。**

## 二、多人 + 多 AI 怎么协作

这是这个项目区别于普通小项目的地方：**我们每个人用的 AI 不一样，流程也不一样。**

### 原则：约束产出，不约束过程

| | 内容 | 怎么管 |
|---|---|---|
| **必须统一** | 什么能合并进 main | CI 自动检查，不可协商 |
| **随你** | 你怎么把代码写出来 | 不管 |

**必须统一的只有四条：**

1. 改动不越出 Issue 声明的范围
2. PR 如实填：改了什么、怎么验证、真实测试输出、已知限制
3. 公共接口和数据模型走统一定义，不各自造一套
4. 不提交密钥

**完全不管的：** 用哪个 AI（Codex / Claude / DeepSeek / Cursor / 手写都行）· 用什么编辑器 · 先写测试还是后写 · 怎么写自己的 prompt · 一个任务分几次做完。

### 为什么不统一流程

- **不同 AI 的盲区不一样。** Codex 漏的东西 Claude 容易发现，反过来也是。统一流程等于让所有人有同一套盲区。
- **过程根本管不住。** 你没法验证队友是不是真按某个流程走的。写了又管不住的规则，只会让整份文档失去可信度。
- **强推流程会赶走人。** 业余时间写代码，多一道他不认同的手续，结果不是他照做，是他不做了。

类比：不会规定谁用 VSCode 谁用 Vim，但会规定代码必须过测试。

### 落地成三样东西

1. **模块边界清单** —— 24 个模块各自能改哪些目录，写成机器可读的格式
2. **边界检查器** —— PR 声明属于哪个模块，CI 自动比对改了哪些文件，越界直接失败
3. **CODEOWNERS + 分支保护** —— 碰到接口、迁移、服务器配置自动请人审

这样「AI 顺手改了不该改的东西」从**靠自觉**变成**技术上进不了 main**，
而每个人用什么 AI、怎么用，完全自由。

> 检查器已经写好并跑通了：界内放行、越界拒绝、模块写错时列出合法取值、全部 25 份清单可解析。

## 三、需要拍板的事

| 事项 | 建议 | 谁定 |
|---|---|---|
| Windows 优先 vs Web only | Windows 优先 + Web 访客 | PO |
| 回声消除 | 恢复必选 | PO |
| 1440p60 / 摄像头 / 多路共享 / 线程 / 搜索 / 私信 | 全部后置 | PO |
| 邀请码谁能建 | 做成设置，默认仅管理员 | PO |
| 域名 | 不买 baba.vip，用子域 | PO |
| 租哪台机器 | **实测决定，不投票** | 测完再说 |
| 中德混合房落哪个节点 | **实测决定** | 测完再说 |
| **Tech Lead 是谁** | **必须定，且只能一个人** | 全体 |

最后一条是当前最大的风险，而且**和技术无关**。

需要有且只有一个人：拥有接口和数据模型、决定合并、保证 main 随时能跑。这个人不必代码最强，但必须愿意读每个 PR，并且**敢说「不合」**。在这个人定下来之前，不应该开始多模块并行。

---

## 四、下一步

1. 上面的事项逐条落到 **定了 / 要实验 / 先不做** 三类，不留「之后再看看」
2. 先做网络实测（1–2 周，不写正式代码）：中德两端、北京时间 21 点、连续两小时，测延迟丢包和带宽
3. 实测结果出来再决定租机器和房间归属
4. 然后才开始写第一条端到端链路

**顺序不能反。** 在网络数字存在之前写界面，是在猜。
