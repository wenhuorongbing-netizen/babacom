# BabaCom Matrix 迁移 PRD

状态：规划提案，关联 [#50](https://github.com/wenhuorongbing-netizen/babacom/issues/50)。2026-10-13；事实基线为 `c9ec3cfab593e9cd03f0cf320a30bcdeae19edd0`。用户已授权制定并发布计划；本 PR 不实施迁移、不变更既有产品契约、不部署或删除代码。技术约定见 [迁移规格](Matrix-migration-spec.md)，执行清单见 [Backlog](Matrix-migration-backlog.md)。

## 1. 摘要

将 BabaCom 从自建桌面语音原型迁移到标准 Matrix 生态，复用成熟账号、社区、消息和实时通信能力，把自己的开发投入集中在私人游戏社区体验、Windows 游戏共享和中德可用性。迁移必须同时收回重复身份、权限、媒体生命周期、构建与测试的维护负担。

Matrix 是协议，不是单一可直接替换的“内核”。本计划评估维护中的开源实现，优先配置和窄扩展；不把创建深度 fork 当作完成迁移。现有代码仍是自建方案，尚未使用 Matrix。

## 3. 背景与问题

朋友群约 25 人，分布中国大陆和德国，希望邀请加入、自托管、无身份证件采集、不按座位收费，并在 Windows 上稳定边玩边聊、观看游戏。当前仓库已有 Electron、FastAPI 准入与 LiveKit 语音原型及六文件 UI 外壳；合并代码不等于已接受完整账号、文字社区、游戏共享或跨境 Alpha。

现有维护负担主要来自：自建身份/权限和媒体准入链；一次性媒体域与未来长期账号/密钥模型不匹配；多层启动/打包/Sandbox 清理归属；测试 fixture 与真实产品证据混淆；界面扩展易与单房间原型绑定。迁移若继续保留两套权威、两套客户端和两套长期测试，只会增加债务。

未完成的真人、物理设备和中德验收仍是需求。旧未结票不是全部都要按旧实现补齐：逐票决定继续维护、迁入新覆盖、或在替代成立后按 superseded 退役，不能伪称已修复。

## 4. 目标与可衡量结果

1. **朋友可以真正迁入。** Windows 用户通过邀请加入同一社区，使用文字与闭麦进入的语音频道；一人共享游戏画面和系统声音，其他人可分别调节说话/游戏音量。真实 10 人语音、1 共享、最多 9 观看连续至少 2 小时；两设备短句每方向至少 19/20 可懂，正常入房至少 9/10。中德链路单独验收。
2. **只有一套可维护的产品。** 新链路中身份、成员、房间、消息只有一个权威；未引入协议/加密核心私有分支。每项定制有用户需求、owner、回归与升级证明；实际演练一次上游升级。切换观察通过后活动旧入口、重复依赖与无消费者代码为零，历史证据保留。
3. **可恢复地上线。** 账号/设备/历史恢复、新写入保护、备份恢复与回滚均实际演练；每日备份，RPO≤24h、RTO≤4h。完成连续两周真实游戏夜，无人因质量回退；失败按预定条件暂停或回退，不能以完成票数替代可用性。

容量数字沿用 [平台 NFR](02-platform-nfr.md) 与 [Scope v2](01-scope-v2.md)。本 PR 没有运行产品或真人验收，也没有凭迁移降低阈值。

## 7. 解决方案与迁移约束

产品方向是采用标准 Matrix 生态。首选候选为维护中的 Element Windows/Web 最小定制；具体实现与部署组合由技术规格中的实验裁定。选择标准协议不意味着游戏共享、通话权限撤销、中德网络和账号恢复自动通过。

**先验证阻断性假设。** Windows 安装包中的游戏画面、真实系统音频、独立麦克风、接收端独立音量、无数字回授及安全停采必须提前证明。失败时停止扩大美术/导航定制，评估另一 Matrix 客户端路径；不靠降低需求或绕回旧准入链宣称成功。

**迁移与化债同步。** 每张功能票附复用/配置/窄扩展判断、旧消费者去向及测试转换；每阶段出口检查重复状态、依赖、定制补丁和生命周期。删除是有验收、有恢复边界的后续工作：先证明替代，再切换观察，最后按逐文件授权退役。历史审计、旧失败结果和用户数据不作为冗余垃圾。

Windows终端自动更新必须可安全失败并保全账号、密钥和历史，不能由开发侧更新上游依赖代替。Web访客在Chrome/Edge有独立加入、文字、语音和权限拒绝旅程；界面明示平台能力差异。崩溃诊断默认本地脱敏，外发由用户明确选择。

可用性还包括备用访问入口、国内可访问状态页、常见网络/证书/容量/数据库事故处置和季度恢复演练。切换入口时不应丢失成员身份和历史，备用资源仍需获得实际使用授权。

**数据与回退是产品能力。** 先查清是否有真实账号、房间、消息、附件、密钥及其所有者。未经盘点不能假设“原型没数据”。Matrix 身份与旧昵称不能直接等同；不能从服务端备份推断设备解密能力。切换后已有新写入时，回到旧数据库快照不构成无损回滚。

**主要假设与最便宜反证：** 标准上游可以承载私域角色/频道（直接 API 负向测试）；可承载游戏音频（真实包双设备实验）；可持续维护（一次相邻版本升级）；可承受中德网络与预算（高峰/强制中继实测）；用户可以恢复历史（新设备密钥恢复与隔离备份恢复）。各反证进入独立票，不作为未验证承诺。

## 8. 发布、节奏与完成定义

这是一个大型迁移 Release，拆为多个有出口的迭代，**不是把全部票塞进一个固定日期 Sprint**。当前人员工时、测试设备、节点、数据量未知，不估造速度、完成日期或采购预算。计划按 1–2 周迭代候选推进；实际承诺以已知可用时间为准，最多 80%容量承诺，至少20%留给故障/审查/升级。

阶段为：受限实验契约与盘点 → 原版基线可验证 → Windows 关键证明 → 单一权威纵切片 → 产品宽度与运行保障 → 真实负载/跨境 → 切换与两周观察及消费者断接 → 逐文件退役。首个Sprint仅交付隔离原版、两个合成账号互通与重启后历史一致，不承诺全场迁移；最终生产政策在实验后签认。9 Epics / 36 父候选票及独立实验子票的优先级、前置、AC、资源与 Ready 条件在 [Backlog](Matrix-migration-backlog.md)；未来实施票初始 DRAFT。

可并行：需求/数据只读盘点、上游许可与运行成本研究、相互独立的行为测试设计。不可争抢：协议/权限契约、依赖锁、基础设施配置、合并队列、同一真实设备与浏览器。先保持最多3个实施/审查工作流；review或资源不足时降低并行度。

全计划 Done 要求：所有 Must 能力通过相应证据层级；未做项由 Jack 明确接受并记录而非静默勾选；数据/恢复/升级/切换观察通过；旧活动链按 M33/M34 退役；旧 Issue 逐项有真实处置；无未处理发布阻断项。R03/R04 提前暴露的上游能力可验证复用，但不挤掉稳定期，也不因按钮存在签收。
