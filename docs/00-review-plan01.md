# 评审：现有规划文档 vs plan01.md

> 输入：`scope.html`（84 功能 / 3 可选 / 34 排除 / 13–16 周）、`teams.html`（8 域 / 24 模块 / 105 agents / 7 冻结契约）、本地 `plan01.md`（工程可行性评审 + 协作方法论）。
> 结论：**方向正确，但 `scope.html` 现在还不能被称为「已裁决的功能范围」。** 下面 12 条是必须先解决的冲突与缺口，每条给出建议裁决。

---

## A. 直接冲突（两份文档说法不一致，必须二选一）

### A1 平台形态：`Web only` ↔ `Windows-first`

- `scope.html` → 「Platform, appearance, account · Web only」
- `plan01.md` → Windows 客户端是完整体验，Web 是低摩擦访客入口

**建议裁决：Windows 客户端优先，Web 为访客入口。**

理由不是偏好，是能力边界。下列功能在纯浏览器里做不到或严重打折：

| 功能 | 浏览器 | Electron 客户端 |
|---|---|---|
| 全局静音/闭音快捷键（游戏全屏时） | 做不到 | `globalShortcut` 可用 |
| Windows 系统音频捕获（游戏声音） | 只能分享标签页音频，且需用户勾选 | `desktopCapturer` + loopback |
| 托盘常驻 / 长期挂频道 | 关标签就断 | 可以 |
| 自动更新 | 刷新页面 | 有 |
| 转播 Discord/Oopz 窗口（后期） | 做不到 | 可以 |

**连带效果：`scope.html` 里「Mute/deafen hotkeys 尚未解决」这个待决项直接消失**——它只在 web-only 假设下才是难题。这也是 A1 应该先裁决的原因：它一次性关掉一个 open question。

Web 访客版第一阶段只需要：打开邀请链接 → 昵称 → 加入语音/文字 → 看别人共享 → 基础音量。不承诺共享、不承诺快捷键。

### A2 回声消除被列入「排除」

`scope.html` 的 34 项排除里包含 **Echo cancellation / Noise suppression / Automatic gain control**。

**建议裁决：AEC 恢复为必选（默认开启，可在设置中关闭）。**

- 这三项是 `getUserMedia` 的**默认行为**，「排除」意味着主动写代码关掉它们，成本比保留更高。
- 只要有一个成员不戴耳机，整个房间就会持续回声。这是可用性下限，不是音质优化。
- NS/AGC 可以保留为「默认开、允许关」，给用麦克风放游戏声的人一个出口。

### A3 组织规模：105 agents ↔ 3 名业余开发者

`teams.html` 假设 24 模块 × 4 角色 = 105 agents，7 个契约全部由 1 名 coordinator 拥有。

**问题不在 agent 数量，在于吞吐上限是 review 带宽，不是并发数。** 24 个模块同时产出 PR，全部撞到同一个人身上审查、同一条迁移序列上排队。wave 2 声称「九个模块真正并行」，实际会变成九个 PR 在队列里等一个人。

**建议裁决：**
- wave 0 实际并行度压到 **3–4 个模块**，跑通纵切片后再放大。
- 契约所有权可以拆：DB schema + repo layout 归 coordinator，其余五个契约各指派一个 DRI，coordinator 保留否决权。
- 保留 24 模块的**划分**（它切得很好），但不要求它们同时开工。

## B. 缺口（现有文档没写，但缺了会翻车）

### B1 没有 vertical slice 关卡

`teams.html` 按模块横切，wave 2 才开始铺开，但**没有任何一个里程碑要求「一条端到端链路先跑通」**。

**建议补一个 M0 出口条件：**

```
Electron 启动 → 取 token → 加入房间 → 发布麦克风
→ 另一台真实电脑（国内 ↔ 德国）听见 → 静音 → 退出
```

这条链路跑通之前，任何 UI 模块都不应开工。它同时验证：token 契约、LiveKit 配置、跨境网络、客户端打包——四个最贵的未知。

### B2 缺少「稳定性」发布阶段

自动重连、睡眠唤醒恢复、USB/蓝牙设备热插拔、自动更新、备份、监控，在 `teams.html` 里散落在 1.3 / 4.3 / 8.2，但 build order 的三个 release 里**没有它们的位置**。结果必然是被「附件、反应、主题」挤掉。

**建议：在 01（可玩）和 02（宜居）之间插入独立的「稳定 Alpha」阶段**，见 [`01-scope-v2.md`](01-scope-v2.md)。

### B3 成本模型是空的

`scope.html` 开头承诺「what the total actually costs to build」，正文没有任何成本段。

没有下面四个输入值就不能声称算过成本：峰值同时语音人数、峰值同时共享路数、平均观看人数、每月共享小时数。

→ 已补：[`03-cost-model.md`](03-cost-model.md)。**结论是 1440p60 会直接击穿常见 VPS 流量包**，这是它必须后置的硬理由。

### B4 没有平台能力矩阵

Windows 客户端 / 桌面浏览器 / 手机浏览器 各支持什么，必须写死，否则「网页版为什么不能共享系统声音」会被反复问。

→ 已补：[`02-platform-nfr.md`](02-platform-nfr.md)。

### B5 没有非功能需求和验收负载

「84 个功能全做完」不等于可用。缺：并发上限、可接受延迟/丢包、重连时间、备份 RPO、日志留存。

→ 已补：[`02-platform-nfr.md`](02-platform-nfr.md)。Alpha 验收负载定为：25 注册成员 / 峰值 10 人同时语音 / 同时 1 路共享 / 最多 9 人观看。

### B6 媒体拓扑没有裁决

`teams.html` 的待决 #6「One room or two」是**唯一一个会改变架构而不只是改变工作量**的待决项。

必须明确：一个中德混合房间由**哪一台**媒体服务器承载。LiveKit 多区域部署可以让不同房间落在不同节点，但**一个房间必须完整落在一个节点上**——加一台欧洲服务器不会自动把同一个房间切成「国内一半在亚洲、欧洲一半在欧洲」。

→ 建议裁决与备选方案见 [`04-open-decisions.md`](04-open-decisions.md)。

### B7 功能表缺少运维侧条目

`scope.html` 的 84 项里没有：

移除成员 · 撤销会话 · 撤销邀请码 · 数据库迁移 · 发布回滚 · 网络诊断面板 · TURN 回退 · 设备热插拔 · 睡眠恢复

这些不是「nice to have」，是没有它们就无法运营一个私人服务器的最小集。

## D. 一条省钱建议

`baba.vip` 一年 ¥40000 没有必要。WebRTC 生产部署需要的是**可信域名 + 有效 TLS 证书**，不是品牌域名。现有域名加子域即可：

```
app.<现有域名>        控制面 / Web
api.<现有域名>        FastAPI
rtc-asia.<现有域名>   LiveKit 亚洲节点
rtc-eu.<现有域名>     LiveKit 欧洲节点
```

省下的钱应该花在 B3 里那台走优质回国线路的媒体服务器上——那笔钱直接决定产品能不能用，域名不决定。

## 裁决后 `scope.html` 需要的最小修改

一句话版本：

> Windows-first，不再写 web-only；回声消除从「排除」移回「必选」；Release 01 限制为单路共享、最高 1080p；补入成员移除、会话撤销、备份、监控、重连与设备生命周期；线程、搜索、复杂权限、DM、摄像头、多路 1440p60 全部后置；补上成本模型和平台能力矩阵。

在这些改动落地之前，`scope.html` 的准确标题应该是 **Brainstorm Selection Summary**，而不是「功能范围裁决」。
